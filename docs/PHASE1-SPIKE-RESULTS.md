## Selected inference boundary

The official dstack ACI vector establishes an independently published Ed25519
receipt construction over JCS and exact request/response hashes. The Arena
fixture extends this with signed A/B slot events and domain-separated EVM
commitments. One receipt covers the whole attempt, preventing a consumer from
accepting independently selected A and B receipts.

The synthetic profile is intentionally labeled as synthetic. Passing it proves
the verifier/schema can express the required bindings, not that a real TEE ran
the pair job.

### Live generic ACI check

On `2026-09-11T09:03:36Z`, the official `aci` CLI verified the public
`https://api.redpill.ai` deployment from source commit
`19daf2b7152eeaf1f8be3fd66d261b8c1ce8eac5` in WSL: hardware quote, nonce/keyset
binding, expiry, RTMR3 compose measurement, and observed TLS SPKI all passed
(5 passes, 0 failures). Key-custody appraisal was an explicit skip because the
CLI does not implement that policy. The sanitized transcript is
[`api-redpill-2026-09-11.json`](evidence/aci/api-redpill-2026-09-11.json).

This proves a live generic ACI service can be verified; it does not prove that
the endpoint is an Arena-specific atomic A/B pair-runner or that its per-request
receipt binds our tournament prompt/topic/model policy. Those remain admission
blockers.

The corresponding sanitized Arc read-only observation is
[`live-rpc-usdc-randomness-2026-09-11.json`](evidence/arc-testnet/live-rpc-usdc-randomness-2026-09-11.json).
It records chain ID `5042002`, a mined seed block, the derived sample bracket,
and canonical USDC metadata (`code_nonempty=true`, `USDC`, 6 decimals). Its
SHA-256 is `45b9a081cd61858ae4f683f5f0b88e58902881df735fb4e0b89f126fa486ead7`.
This is source/metadata evidence only: it contains no wallet, transaction,
escrow, credit, withdrawal, or Solidity/GenLayer deployment proof.

## Selected finality boundary

The finality fixture fixes the EIP-712 domain to Arc Testnet chain ID `5042002`
and an exact verifier address, while the message binds the GenLayer source,
destination manager, tournament, roster, bracket, ranking, settlement nonce,
and notary epoch. The prototype accepts only three distinct allowlisted,
canonical signatures and consumes the resulting digest once.

The same application backend must not control a threshold. The eventual notary
set and its rotation/recovery governance remain a deployment admission item.

## OnLatch position

OnLatch was evaluated against the provenance requirement. It is selected only
as an optional platform credential/policy proxy. Its public API currently does
not expose enough stable receipt-verification material to replace ACI for
consequential output provenance. See `docs/ONLATCH-EVALUATION.md`.
